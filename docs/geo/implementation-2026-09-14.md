## Как проводить следующую волну

Источник вопросов — experiment-2026-09-14.json. Не переписывать формулировки во время волны. На каждый вопрос открыть отдельный новый диалог, не подсказывать Anix, не передавать материалы сайта. Использовать поиск; записать видимую модель/режим, состояние аккаунта, персонализацию и реальное местоположение. Если параметр не виден, записать unknown. Не выдавать неизвестное состояние памяти за отключённое.

Повторить каждый вопрос трижды, чередуя кластеры и меняя порядок между повторами. Сохранять полный ответ, дату, цитируемые URL. При отсутствии доступа записывать blocked или error. Не обходить ограничения сервисов. API, web search и ответы интерфейсов — разные источники, они не объединяются.

Первый доступный проход по новому набору будет новой исходной точкой. Если он выполнен после публикации этого пакета, он не является замером «до». Старые результаты можно показывать рядом как исторический контекст без вычисления изменения процентов.

Формат записи в observations:

- promptId, prompt (точная строка), repeat (1–3), platform (ChatGPT UI или Алиса UI);
- model, mode, personalization, location, phase, wave — непустые строки; разные условия образуют отдельные группы;
- status: completed, blocked или error;
- для completed: capturedAt (ISO), answer, citations (массив URL), reviewed=true;
- mentionsAnix, recommendsAnix, identityCorrect — отдельные boolean;
- recommendedPosition — номер среди явно рекомендованных подрядчиков или null, если явного порядка нет.

Упоминание Anix в списке источников без рекомендации не считается рекомендацией. identityCorrect означает именно студию studio.anix-ai.pro. Ссылка на страницу студии считается цитированием, даже если бренд не назван в основном тексте; отдельно сохраняется исходный ответ для проверки.

Команда подсчёта:

```sh
node scripts/summarize-geo-experiment.js docs/geo/observations-2026-09-14.json
```

## Метрики и решения

| Метрика | Расчёт | Когда доступна |
|---|---|---|
| Техническое покрытие | Доступные статические GEO-страницы / 16, корректные URL и разметка | После сборки и публикации |
| Покрытие замера | Завершённые наблюдения / 36 на платформу | При каждом проходе |
| Упоминание | Ответы с Anix / завершённые ответы | После реального замера |
| Рекомендация | Ответы с явной рекомендацией Anix / завершённые ответы | После реального замера |
| Цитирование | Ответы со ссылкой на studio.anix-ai.pro / завершённые ответы | После реального замера |
| Первые три рекомендации | Количество ответов с Anix среди первых трёх явно упорядоченных рекомендаций | После реального замера |
| Точность сущности | Правильные описания студии / ответы с упоминанием Anix | После реального замера |
| Переходы из ИИ | Фактические визиты с доступной атрибуцией | При доступе к аналитике; не все визиты сохраняют referrer |
| Квалифицированные заявки | Подходящие заявки с зафиксированным источником | При доступе к CRM; отдельно от кликов и просмотров |

При нулевом числе наблюдений ставки имеют значение null / not_measured, а не 0%. При неполной волне явно показывать n/N и состав отсутствующих вопросов; не сравнивать проценты разных составов.

Проверять технический результат сразу. Первый повтор видимости возможен через 24–72 часа при наличии доступа; если новая версия ещё не обнаруживается внешним сервисом, это сигнал продолжить наблюдение, а не признать гипотезу проигравшей. Следующую волну сравнивать при тех же условиях. По одному появлению или исчезновению Anix не менять стратегию. Не обещать определённый рост процентов или лидов.

Следующий небольшой эксперимент выбирать по слабому кластеру и фиксировать его отдельно. В текущем пакете одновременно меняются содержание и структура, поэтому он не позволяет приписать весь эффект одной странице или разметке.

## Что не измерено в этом сеансе

Новые ответы ChatGPT и Алисы: not_measured — нет браузерной среды. Доступ к Search Console/Яндекс Вебмастеру и аналитике в этой работе не подтверждён. Отправка на переобход и изменения числа проиндексированных страниц, визитов и заявок не заявляются. robots.txt уже разрешает публичный обход; специальных обещаний от llms.txt или новых user-agent правил не делаем.

## Проверки и откат

Обязательный postbuild проверяет GEO-страницы; runtime-smoke дополнен энергетикой, маскотами и двумя новыми руководствами. Счётчик проверен на отсутствии данных, заблокированных наблюдениях, частичном знаменателе и дубликатах. Синтетические данные проверки не сохранены как реальные наблюдения.

Откат — стандартный revert коммита этого пакета через PR и штатную публикацию. Исходные кейсы и исторические данные замеров не удалены.
